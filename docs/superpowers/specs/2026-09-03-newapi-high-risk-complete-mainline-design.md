# NewAPI 上游高风险业务链路完整融合（Main 线）设计

## 目标

在不覆盖本地二开业务语义的前提下，把已确认缺失的上游高风险能力完整接入当前 NewAPI：

- JavaScript task-plugin/sandbox；
- artifact 存储、访问控制和任务产物展示；
- 视频代理新链路；
- 密码登录传输加密；
- wallet/quota 64 位 schema；
- 与这些能力直接相关的 Go、relaykit、Bun、前端和 Electron 依赖。

生产数据库迁移、生产部署、远端推送不属于本次源码融合，继续单独保留。

## 约束

1. 直接在 `main` 线执行，不创建分支。
2. 禁止整树 `merge`、`rebase`、`cherry-pick`、强制覆盖和 `reset --hard`。
3. 不删除当前图片任务、支付、订阅、推荐、提现、渠道故障转移、计费和权限状态链路。
4. 上游代码只能按功能边界手工融合；本地行为优先于同名但语义不同的上游实现。
5. 新增生产代码先有能正确失败的测试；每个阶段独立提交并可用 `git revert` 回滚。
6. 密码加密默认只改变浏览器传输，不改变数据库密码哈希格式。
7. 额度内部统一使用 `int64`，数据库额度列使用 `bigint`；对外 JSON 保持数字字段兼容，不能静默溢出。
8. task-plugin 默认关闭，只有管理员显式启用并通过权限校验后才可执行插件。
9. 插件只能通过受限协议访问 HTTP、文件、环境和任务上下文；禁止任意宿主进程执行。
10. artifact 下载必须经过任务归属、签名、过期和权限检查。

## 组件边界

### 认证加密

后端提供公钥和 key id，前端使用 Web Crypto RSA-OAEP/SHA-256 加密密码；服务端在登录、注册、找回密码和管理员改密入口统一解密。旧客户端在兼容窗口内仍可使用原字段，服务端不把密文写入日志。

### 额度与钱包

将用户、Token、日志、任务、兑换码、充值、结算 DTO、relaykit 元数据和 billing expression 的额度链路统一为 `int64`。数据库迁移采用可重复执行的列类型升级和启动前 schema 检查，不在应用启动时自动把有风险的旧 schema 强行转换。

### artifact 与视频

统一任务产物描述、存储 key、媒体类型、大小、过期时间和访问策略。视频代理只负责受控地读取任务产物或上游 URL，继续复用当前任务归属、渠道代理、超时、清理和结算边界。

### JS 插件

沿用上游协议、注册表和插件脚本，但将执行入口接入本地任务生命周期。插件运行时、协议路由、渠道选择、调试接口、审计和管理员配置分别隔离；内置插件逐个替代当前内置任务适配器，保留任务计费和失败退款。

## 错误与回滚

- 插件未启用、无权限、协议非法、超时或无渠道时返回明确错误，不降级执行任意代码。
- 加密失败只返回通用认证错误，服务端日志只记录 key id 和错误类别。
- 额度迁移前提供 schema 检查和回滚 SQL；发现旧列、溢出或迁移失败时阻止进入新链路。
- 每个阶段单独提交；回归时按阶段 `git revert`，不使用破坏性 Git 操作。

## 验证标准

- Go：相关包测试、根模块 `go test ./... -count=1`、race 重点测试。
- Web：`bun run typecheck`、相关 Vitest、`bun run build`。
- Schema：SQLite 单元迁移测试、PostgreSQL dry-run/容器演练脚本和旧 schema 拒绝测试。
- 安全：插件越权、任意文件/进程访问、artifact 越权下载、密文日志泄露和旧客户端兼容测试。
- 交付前必须通过 `gofmt`、前端格式检查、`git diff --check` 和敏感文件扫描。
