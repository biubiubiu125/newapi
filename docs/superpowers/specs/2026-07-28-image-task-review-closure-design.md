# NewAPI 图片异步任务闭环修复设计

日期：2026-07-28

## 目标与范围

本次修复只处理 NewAPI 当前工作树中对外图片异步任务 API 的六个已确认缺陷：人工复核无收口入口、共享磁盘预留失真、结果下载内存放大、批量任务心跳误取消、孤儿扫描饥饿，以及非 `b64_json` 内联结果绕过体积限制。不修改 RKAPI Image，不改变已有创建、鉴权、幂等、预扣、结算和退款的正常路径。

## 方案一：人工复核闭环

新增仅 `RootAuth` 可访问的管理接口：

`POST /api/task/:task_id/image-review`

请求体包含必填 `action`，支持：

- `retry_poll`：仅允许公开图片任务、当前状态为 `REVIEW`、存在上游任务 ID 且渠道仍可用。通过数据库 CAS 将任务恢复为可轮询状态，保留预扣额度和 settlement record，不重新提交上游。
- `retry_settlement`：仅允许 `SUCCESS + REVIEW`，且结果或已捕获计费证据仍完整。通过 CAS 恢复为 `PENDING`，由现有 worker 继续原子结算。
- `confirm_failed_refund`：仅允许 `FAILURE + REVIEW`。通过专用事务锁定 task 与 settlement record，确认不存在已完成消费结算后执行原子退款，并保持重复调用幂等。

接口返回更新后的任务状态；非法状态迁移返回 `409`，任务不存在返回 `404`，校验或事务失败不做部分状态写入。每次操作记录管理员 ID、任务 ID、动作、原状态、结果和失败原因，避免依赖直接 SQL 修改资金状态。

## 方案二：共享磁盘容量账本

共享 reservation marker 表示“尚未由真实文件覆盖的预留字节”，而不是始终保存完整预留量。marker 与目标缓存文件绑定，容量统计按真实文件大小加剩余预留计算，避免增长中的文件和 marker 双计数。

活跃共享预留启动轻量续租，周期性刷新 marker 修改时间；`Commit` 和 `Release` 必须先停止续租再删除 marker。只有超过 stale 阈值且没有续租的 marker 才能回收。新增未知长度分块增长、并发预留及超过 stale 周期仍存活的测试。

## 方案三：结果下载资源保护

共享文件结果不再使用 `os.ReadFile`。处理流程为：鉴权和生命周期校验、获取下载并发槽、打开文件、分块完成大小/SHA256/JSON 校验、seek 回文件头、通过流式响应发送。

增加单进程全局及单 Token 下载并发限制。达到限制返回可重试 `429` 或 `503`，并带 `Retry-After`。内联结果虽然仍需由数据库载入，也必须先经过相同的并发入口，确保单 Token 无法同时持有大量大结果。

## 方案四：批量租约心跳

批次仍共享运行上下文，但单任务续租失败后先读取持久化状态：任务已经进入 `FAILURE`、`SETTLED` 或 `REVIEW` 等正常终态时，只停止该任务自己的心跳；任务仍处于可运行状态且租约确实丢失时，才取消整个批次。数据库读取失败仍按保守策略取消。

测试必须覆盖“第一个任务正常完成后超过心跳周期，后续任务不被取消”以及“运行中任务真实丢失租约时批次仍会取消”。

## 方案五：孤儿扫描游标

孤儿扫描新增跨轮次原子游标，查询条件改为 `id > cursor ORDER BY id ASC LIMIT n`。每轮推进到最后一条候选；到达尾部后回绕为零。被判定为活跃节点积压的低 ID 任务不再永久挡住后续失联节点任务。

游标只影响扫描顺序，不改变孤儿判定、退款条件或 CAS 保护。

## 方案六：统一内联结果上限

结果是否包含 `b64_json` 只决定是否值得在可信共享缓存中外置，不再决定是否执行内联上限。凡最终写入 `tasks.data` 的结果都执行 `IMAGE_TASK_RESULT_INLINE_MAX_MB`；超限时沿用现有人工复核语义，避免数据库 packet 错误和无限膨胀。

## 验证标准

- WSL Debian 中运行相关包测试、`go vet` 和全仓 `go test ./...`。
- OpenAPI 文档包含管理接口及错误语义，JSON 可解析且本地引用有效。
- `git diff --check` 无错误，最终差异不包含 RKAPI Image、临时文件、测试数据库或构建产物。
